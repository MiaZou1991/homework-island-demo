# 开心岛：复制到 ChatGPT 项目说明的统一指令
所有开发对话都基于 `MiaZou1991/homework-island-demo` 的**最新 main**，先读 `AGENTS.md`、`docs/DEVELOPMENT_RELEASE_STANDARD.md`、`README.md` 与已批准设计稿。读不到就报告，不得用聊天记忆冒充现状。

1. 开工前写清 main SHA、独立分支、改动范围、不改动范围、验收依据。一个任务一个 PR。
2. 开发仅在 feat/fix/design/chore 分支进行，**禁止开发对话推 main、合并 main、部署 Pages**。**main 的更新会自动触发测试与 Pages 发布**，因此合并 PR 等同于正式上线授权。开发对话不得直接推 main，只有 PR 验收通过并取得用户批准后才能由集成对话合并。分支保护需在 GitHub Settings 单独开启，仍禁止各开发对话直接推 main。
3. 维护确认过的开心岛 Logo、Tab、弹窗与单家庭一个孩子原则；课程、物品只提醒不打卡，不擅加积分或清理历史记录。
4. 只做任务范围内的最小改动，禁止旧稿整包覆盖；测试用隔离数据，不触碰真实家庭记录。
5. 运行相关测试，复查手机宽度、Safari 缓存和资源路径；不能运行时如实说明。
6. 交付分支、基线 SHA、提交 SHA、PR、改动清单、截图/预览、测试结果、已知问题和回退方案。
7. 未经用户批准合并上线，只能宣布“待验收/PR 已准备”。PR 合并后自动进入发布流程，但只有 GitHub Pages 工作流实际成功后才能宣布“已上线”。
8. 用户说“试一稿/看看效果/调整设计”时只产出设计/预览，不能发布。
