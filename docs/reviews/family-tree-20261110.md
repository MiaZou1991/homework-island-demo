## 完成的前端与业务逻辑
- **成长回忆**：按日期、类别归档；新增、修改、删除；展示作者；非作者不能改删；日期和内容长度校验。
- **家庭便签**：全家可读、可回复；按作者保留修改删除权；删除便签级联删除该便签回复；回复可编辑删除。
- **爱心**：选择一个家庭成员发送；收件箱/发件箱、确认收到；业务模型只向发送人和接收人返回爱心，其他身份不能通过 UI 查看。
- **场景入口**：走到家庭树，进入场景近景后可点击进入完整家庭树页面，关闭后回到原步行位置。
- **兼容性**：采用已批准的木牌、绿色按钮、纸面板素材和统一字体；支持 320、375、390、430 手机宽度；保留纯文本与按钮可访问性；用户输入 HTML 转义避免渲染为标签。

## 真实数据安全阻断项（不可略过）
- 当前家庭树为**隔离的本机互动体验**，`family-tree.html` 使用 `kaixin_family_tree_public_preview_v1` 和 `kaixin_family_tree_private_preview_v1` 本地独立键；预置演示内容，刷新后仍可回看。不修改生产 `getData/saveData`、现有云端家庭 JSON、积分或历史数据。
- 页面身份选择仅用于切换体验视角，**不构成登录/身份认证**。私密爱心在当前共享浏览器的 localStorage 内并无真实访问控制，因此**不可以作为生产隐私能力上线**。UI 中明确展示体验提示。
- 若需要真正跨设备家庭便签/爱心：安全分支须先落地可信身份、后端按成员隔离的爱心数据存储/RLS、并发版本比较/幂等、读写校验和备份。再单独创建对接 PR，禁止将爱心写入全家共享 JSON。
- 本 PR 不提交正式生产写入。不能将功能预览通过解读为已完成安全上线。

- 不再使用「成长回忆」「家庭便签」「成长记录」三个互相混淆的导航名称；主导航统一为**「家庭记录」｜「送爱心」**。
- 家庭记录中合并成长回忆与家庭便签，使用一个按日期排序的时间流，保留类型筛选（全部／成长回忆／家庭便签）、新增编辑删除、家人回复；两类记录均可回复。
- 原设计右侧「成长记录」指的是**小树成长历程**，不是另一份成长回忆；取消独立 Tab，改放在顶部「我们的小树」状态卡片中，显示累计爱心、树的成长阶段与下一阶段还需的爱心。
- 成长规则以爱心信件数量为条件；本阶段演示用 0／3／8／16 四个阶段，仅用于视觉，不换算积分、不发放奖励；发布家庭记录或回复不会增加爱心。
