# 开心岛 V2 同步：家长冲突裁决与历史数据保护（2026-11-10）

## 已确认的业务决策
1. 两台设备修改同一条记录发生冲突时，**两份修改都保留**，由家长明确选用一份；禁止“最后写入覆盖”。
2. **保留全部既有积分、成长、奖励及小岛建设历史**，不因此次同步修复新增积分计算或奖励。
3. 课程、出门物品仍仅提醒，不增加打卡。

## 本次代码增量
- `dist/v2-conflict-review.js`：从 V2 合并内核返回的 `conflict` 生成家长待决记录，展示云端版和本机版；家长可选远端或本地提案。
- `checks/v2-conflict-review.cjs`：覆盖同一字段不同修改、独立完成字段保留、历史积分/成长/奖励不变化、未经选择不能走“最新覆盖”。
- **纯计算、未接正式页面、未触生产数据库**；不能仅凭测试通过就标记数据已同步。

## 生产接入必须遵循的流程
1. 先将冲突操作和两份快照写入持久化队列；若保存失败，不能关闭冲突提示并冒充成功。
2. 家长明确选择后，持久化决策；选本机版时生成**新** `operationId`。选云端版时也必须保留未选版本供查询/导出。
3. 刷新最新 `revision`，对 `family_save_v2` 做 CAS；版本再次冲突须重读并复核，不能盲重试覆盖。
4. 保存成功**且云端读回一致**后，再清除原 pending；丢 ACK 或中途退出均可无损恢复。
5. 本模块对“删除与编辑”“远端已删除”等冲突不自动做家长端裁决：必须继续停留待处理状态，待界面与权限方案补齐。
6. 原有 `points`、`demoGrowth` 等顶层关联变化由 `planTransition` 标记为 `safe:false`；不得丢弃这些字段后上传剩余作业操作，也不得在重试时重复发奖。
7. 孩子完成作业需要服务端专用授权写入路径，不能复用家长完整 payload 写权限。

## 上线阻断
- V2 核心和本模块仍未接入正式 `dist/app.js`、`dist/cloud-sync.js`；旧版整份 JSON 发送必须完全停止后才允许启用 V2。
- 在隔离 staging 跑真实父/子 JWT、CAS 冲突、断网恢复、WebKit 多端和真实手机验证。
- 先导出每台设备的 local-v1 pending/家庭记录，再备份生产数据并验证恢复；无法推断来源的旧 pending **不得**自动覆盖云端。
- 检查所有积分和成长副作用；不得新增积分逻辑，不得抹去历史。
- 未通过上述条件，PR 保持 Draft，不合并到 main、不部署生产。
